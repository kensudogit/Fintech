ARCHITECTURE エンドツーエンド構成

意図分類 → 専門エージェント実行 → 応答統合。ナレッジは PostgreSQL + 埋め込み検索、行動はイベント履歴からプロファイル更新します。

  • UI — FastAPI 静的画面（本画面）· Next.js · Streamlit
  • API — FastAPI /api/v1/* · Swagger /docs
  • Agents — operations · personalization · knowledge（LangGraph）
  • DB — users · behavior_events · knowledge_documents · conversation_*
PACKAGES Fintechパッケージ事業

生成AI・時系列予測・深層学習を組み合わせ、金融意思決定エージェントを現場運用します。

  • 企業価値推定・高度予測 — 財務/株価/金利 × ニュース/BM/センチメント
  • 意思決定構造エンジン — 定性・定量統合、基準木、シナリオ、反対仮説
  • TempestAI融資稟議AI — 定性情報込みの稟議解析・推奨判断
  • TempestAIビジネスマッチングAI — 取引先×外部情報の企業間マッチング
RECOMMENDED 最短の進め方

初回はサンプル投入後、企業価値推定 → 決裁構造の順が最短です。

  • 「ノースウィンド製造の企業価値を推定して」→ EV / 公正株価 / 予測パス
  • 「メディブリッジの株価を高度予測して」→ 時系列＋センチメント
  • 「グリーンロジのセンチメントを踏まえて公正価値を出して」→ 慎重スタンス例
  • 続けて「決裁構造を変えて」→ 基準木・シナリオ・反対仮説へ接続
  • 「融資稟議を審査して」/「マッチング候補を出して」で実務パッケージへ
VALUATION 企業価値推定・高度予測の使い方

生成AI・時系列予測・深層学習を組み合わせ、財務・株価・金利などの定量と、 ニュース・ビジネスモデル・センチメントなどの定性を統合し、 真の企業価値推定と高度予測を行います。

  • 定量 — 財務諸表指標、株価系列、金利/WACC、モメンタム
  • 定性NLP — ニュース/BM叙述のセンチメント・テーマ抽出（言語処理）
  • 時系列予測 — OLSトレンド＋指数平滑、ベース/上下バンド
  • 深層融合 — 2層ネットワークで value / risk / growth ヘッド
  • 出力 — 真のEV、公正株価、市場ギャップ、意思決定スタンス

DEMO UNIVERSE

  • NWD ノースウィンド製造（精密部品）— 成長・強気センチメント寄り
  • MDB メディブリッジ（医療機器卸）— ディフェンシブ＋提携テーマ
  • GLG グリーンロジHD（物流）— レバレッジ・コスト圧力で慎重寄り

OUTPUT CHECKLIST（右欄「TempestAI 結果」）

  • EV / 公正株価 / 市場価格 — ギャップ（アップサイド）を確認
  • 定性ラベル（強気・中立・弱気）と融合スコア
  • 予測パス — チャット内の base / up / down
  • スタンス — 積増し / 中立保有 / 縮小

API: POST /api/v1/tempest/valuation/analyze　 銘柄一覧: GET /api/v1/tempest/valuation/universe　 意図: value_forecast

EVIDENCE 意思決定に利する情報の投入

口頭補足を禁止し、定性・定量を Evidence Ledger に載せてから決裁します。

  • 画面フォーム「意思決定情報の投入」から構造化投入（種別・案件・寄与理由）
  • 自由文投入: 自動で定量パース（例 DSCR=0.95）または定性分類
  • チャット:「意思決定情報を投入: …」→ 投入後に構造を再計算
  • API: POST /api/v1/tempest/evidence / .../evidence/text
  • 「投入して意思決定を再実行」で基準木・スタンスへ即反映
PIPELINE 推奨フロー（情報投入 → 決裁構造）

単発のスコアで終わらせず、投入エビデンスを意思決定構造に接続します。

  • ① 定性/定量の意思決定情報を投入（寄与理由を必ず書く）
  • ② 「決裁構造を変えて」または「投入して再実行」で構造再計算
  • ③ 「企業価値を推定して」で EV・予測を取得（任意）
  • ④ 「融資稟議を審査して」等の実務パッケージへ接続
DECISION 意思決定構造エンジンの使い方

目的は処理速度の向上ではなく、誰が・何を根拠に・どの反対仮説を残して決めるかを 再現可能・反証可能な形に変えることです。

  • Evidence Ledger — 定性・定量を同一台帳に載せ、口頭補足を廃止
  • 基準木 — 収益返済 / 実行蓋然性 / マクロ整合 / 組織学習
  • シナリオ3分岐 — ベース / アップサイド / ダウンサイド＋トリガー
  • Challenge Board — 反対仮説と回答責任者を必須化
  • ガバナンス — 統合スコア帯で決裁権限・必須成果物を自動割当

画面右の「TempestAI 結果」にスタンス・統合スコア・構造転換サマリが出ます。 詳細はチャットの「TempestAI意思決定構造」見出しを確認してください。

詳細利用手順

  1. 1. 起動確認

    API ヘルスと RAG ドキュメント数を画面右上で確認します。

    • Health: /api/v1/health
    • Docs: /docs
    • デモユーザー: demo-user-001（既定）
  2. 2. データ投入

    「サンプルデータを投入」または POST /api/v1/seed?force=true でデモデータを登録します（意思決定原則・審査観点ナレッジ含む）。

  3. 3. 意思決定情報の投入（Evidence）

    決裁に効く材料だけを構造化して投入します。decision_relevance（寄与理由）を必ず付けてください。

    • 画面: 種別・案件・タイトル・寄与・本文 →「情報を投入」
    • 定量例: 種別 quantitative / タイトル DSCR / 値 0.95 / 単位 x
    • チャット例:「意思決定情報を投入: 原材料交渉が難航しマージン圧迫」
    • 反映確認: 右欄 TempestAI 結果 + Evidence Ledger の ingested 行
  4. 4. 企業価値推定・高度予測

    value_forecast が定量×定性×時系列×深層融合を実行します。

    • 「ノースウィンド製造の企業価値を推定して」（NWD）
    • 「メディブリッジの株価を高度予測して」（MDB）
    • 「グリーンロジのセンチメントを踏まえて公正価値を出して」（GLG）
    • 「企業価値推定と高度予測の枠組みを教えて」（ナレッジ）
    • API: POST /api/v1/tempest/valuation/analyze / GET .../universe
  5. 5. 意思決定構造を変革する

    チャットで構造変革を依頼すると decision_structure が起動し、投入済み Evidence を自動マージします。

    • 汎用:「定性・定量を統合して意思決定構造を変革して」
    • 融資案件:「ノースウィンド製造の決裁構造を変えて」
    • マクロ方針:「与信スタンスを業況と定性で構造化して」
    • API: POST /api/v1/tempest/decision/transform
  6. 6. 出力の読み方

    回答と右カラムで、次をセットで確認します（どれか一つだけでは不十分です）。

    • 企業価値: EV・公正株価・市場価格・アップサイド・評価ラベル
    • 予測: horizon 月の base / upside / downside と予想リターン
    • 定性: センチメント（強気/中立/弱気）とテーマ（需要拡大など）
    • 深層融合: fused_score と value/risk/growth ヘッド
    • 構造変革: From→To、基準木、シナリオ、Challenge Board
    • 次アクション（委員会指標化・モニタリング頻度など）
  7. 7. パッケージ連携

    情報投入 → 価値推定 → 意思決定構造 → 稟議/マッチングの順で接続できます。

    • evidence_intake — 意思決定に利する情報の投入
    • value_forecast — 真の企業価値・高度予測
    • decision_structure — 決裁構造変革（投入 Evidence 反映）
    • loan_screening / b2b_matching / sales_support
  8. 8. 自然言語操作（確認フロー）

    リテール操作デモです。実送金は行いません。

    • 残高:「残高を教えて」
    • 振込:「太郎に3万円振り込んで」→ 確認ボックス表示
    • カード:「カードを一時停止して」→ 確認後にデモ停止
  9. 9. ダッシュボード確認

    投入 Evidence・パッケージカード・ナレッジを確認（GET /api/v1/dashboard）。

ANTI-PATTERNS やってはいけないこと
  • 株価や財務だけで企業価値を決め、ニュース/BM/センチメントを無視する
  • 予測の base だけ見て upside/downside バンドを捨てる
  • 定性を「補足コメント」に落として定量だけで決裁する
  • 反対意見・ダウンサイドを議事録から消す
  • 処理時間短縮だけを成功指標にする（構造変革・価値推定が主目的）
  • Evidence Ledger / シナリオ / Challenge Board なしで本部合議する
OPS NOTES 注意事項（デモ）
  • 企業価値の財務・株価・ニュースはデモデータ（NWD / MDB / GLG）です
  • 時系列・深層融合は説明可能なデモ実装（本番では実データ/モデルに置換）
  • 意思決定ケース・稟議・マッチング企業もデモデータです
  • 振込・カード停止はメモリ上のデモ台帳（再起動でリセット）
  • API キーなしでも LLM_PROVIDER=mock で動作します
  • 本番 LLM 利用時は OPENAI_API_KEY 等を .env に設定
  • PostgreSQL 既定: 127.0.0.1:15432 / DB fintech_ai
